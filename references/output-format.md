# 输出格式规范

审查报告的固定结构、问题性质词表、严重级定义与示例条目。

## 报告结构（固定五段）

```markdown
# PPT 审查报告：<PPT 标题或文件名>

## 一、总体评价
（≤200字：核心主张复述 + 受众/场合判断 + 叙事主线判断 + 最严重问题 Top3 概述。
 若核心主张无法复述，在此显式声明，并说明这是全局性问题。）

## 二、逐页问题清单
（按页码升序，逐条列出。格式见下。）

## 三、结构级问题（跨页）
（不属于单页、属于全局结构的问题：页面顺序调整方案、缺失章节、
 冗余页合并/删除建议、目录与实际结构不一致等。）

## 四、修改优先级路线图
（按 🔴→🟡 排列的执行顺序：第一批先改什么、第二批再改什么，
 让作者可按序执行、逐条勾选。）

## 五、审查局限声明
（文本提取未覆盖的内容：整页图片、SmartArt、演讲备注之外的口头内容等。
 明确哪些结论受此限制。）
```

## 逐条格式（强制）

```markdown
- [P<页码> | <严重级> | <问题性质>]
  **定位**：<逐字引用原文，或精确描述页面位置>
  **问题**：<违反哪项标准（一/二/三/四）+ 为何在导师视角不合格>
  **建议**：<可直接执行的修改：给出改写后的完整措辞 / 需补充的具体数据点 / 明确的页面操作（如"将本页移至 P8 之后并改标题为…"）>
```

## 严重级定义

| 级别 | 判定 | 典型情形 |
|---|---|---|
| 🔴 必须修改 | 存在事实/概念错误，或论证链断裂导致结论不成立 | 术语误用、指标混淆、因果颠倒、无威胁模型的鲁棒性声明、核心主张缺失、论证前提被推翻 |
| 🟡 建议修改 | 内容正确、结论成立，但表达不达标 | 表述模糊、量化缺失、观点隐含、标题非断言、转场不显式、顺序可优化 |
| 🟢 可选优化 | 成立但有更优组织方式 | 页面顺序可调、相邻页可合并、内容可精简 |

**承接类问题的分级（最易判错处，必须按此规则）**：做一次反事实检验——**"翻过这一页，读者能否自行补上那层因果？"**

| 情形 | 判定 |
|---|---|
| 上一页的**前提/设定被下一页的实现直接推翻**（如 P3 威胁模型称黑盒、P4 方法却需模型梯度） | 🔴 |
| 结论页**不回应**前一页留下的核心疑问，且据此得出不可靠的结论 | 🔴 |
| 仅**缺显式转场句**，但读者可自行推断（如 P2 提出问题、P3 直接给设定，缺"据此本文设定如下"） | 🟡 |
| 顺序可更优（如证据页位于结论页之后，但仍可读通） | 🟢 |

判据的核心是：**问题出在"前提"还是"过渡"**。前提被推翻 → 🔴；只是过渡不显式 → 🟡。不要因为问题标签带"承接"二字就按 🔴 处理。

## 问题性质词表（映射到四项标准）

- **标准一 背景与场景**：背景缺失 / 术语未定义 / 场景含糊 / 上下文断裂 / 威胁模型缺失
- **标准二 逐页因果**：页面冗余 / 承接断裂 / 顺序失据 / 转场缺失
- **标准三 逻辑结构**：因果链断裂 / 论证跳步 / 结论缺失 / 量化缺失 / 论证语言失当 / 论证单侧性
- **标准四 观点表达**：观点隐含 / 事实堆砌 / 标题非断言 / 主张与证据错位 / 过度声明

## 示例条目

以下为合格条目的写法标准（原文明；建议给出了可直接粘贴的改写）：

```markdown
- [P7 | 🔴 | 威胁模型缺失]
  **定位**：「对抗训练显著提升了模型安全性」
  **问题**：标准一/三。「安全性」未定义指标与威胁模型——不知攻击者知识（白盒/黑盒）、
  能力（ε 预算）与目标，提升无从检验；「显著」无统计检验支撑。
  **建议**：改为「在 ε≤8/255 的 L∞ 白盒设定下，对抗训练将 PGD-100 攻击成功率
  从 92% 降至 31%（CIFAR-10）」，并在页脚注明攻击配置；如未测黑盒迁移攻击，
  补一句「黑盒迁移场景留作未来工作」以限定声明范围。

- [P12 | 🟡 | 标题非断言]
  **定位**：页题为「实验结果」
  **问题**：标准四。该页实际结论是「剪枝 40% 参数仅损失 1.2% mAP」，
  标题却只给出主题，听众需自行推断观点。
  **建议**：页题改为断言式「剪枝 40% 参数仅损失 1.2% mAP：模型可大幅压缩」，
  页内第一行可再加一句结论句呼应。

- [P15→P16 | 🟡 | 转场缺失]
  **定位**：P15 结束于「注意力图存在高频噪声」，P16 直接展示「多尺度融合模块结构」
  **问题**：标准二。P15 留下的疑问是"噪声如何抑制"，P16 未回应而直接进入新模块，
  读者需自行推断"噪声问题→为什么这个模块能解决"的因果链。**属衔接弱而非论证断裂**：
  两页前提并不冲突，删去任一方整体结论仍成立，故判 🟡。
  **建议**：P16 开头增加一行承接句「针对上述高频噪声，我们引入多尺度融合，
  在下采样前对注意力图做金字塔平滑」；或将 P15 的噪声可视化移入 P16 作为动机。

- [P18→P19 | 🔴 | 承接断裂]
  **定位**：P18「威胁模型：攻击者仅可注入训练数据，无模型权重与梯度访问」；
  P19「以 PGD 迭代优化触发器像素」
  **问题**：标准二/一。P18 建立的前提（无梯度访问）被 P19 的实现直接推翻——
  这不是"少一句过渡"，而是**论证前提不成立**，据此得出的攻击有效性结论不可靠。
  按分级规则（前提被推翻）判 🔴。
  **建议**：二选一并保持两页口径一致——① 若确为黑盒，P19 改为无梯度的触发器搜索；
  ② 若需梯度，P18 威胁模型改为"可访问替代模型（surrogate）"，并说明代理模型假设与迁移代价。
```

## HTML 报告（可选）

当问题条目超过约 30 条或用户要求时，将报告渲染为 HTML（逐条复选框 + 按严重级/标准筛选），
作为交付文件用 present_files 展示，方便作者按路线图逐条勾选执行。
