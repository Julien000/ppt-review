# ppt-review · 学术 PPT 审视与批改技能

> 以资深导师的标准逐页审查演示文稿：概念错误零容忍，页面衔接必须构成完整论证链。

`ppt-review` 是一个 **Agent Skill**（兼容 WorkBuddy / Claude Code 等支持 Agent Skills 的客户端）。它把"帮我看下这个 PPT 有什么问题"这种模糊请求，转化为一份**逐条可定位、可执行、可勾选**的问题清单。

审查对象聚焦于**学术演示文稿**：组会/进度汇报、开题报告、毕业论文答辩、论文分享、项目汇报。

---

## 为什么需要它

学术 PPT 的常见失败模式，从不是"不好看"，而是**论证不成立**：

| 失败模式 | 典型症状 |
|---|---|
| 背景缺失 | 关键术语首次出现即使用，听众不知道前提 |
| 因果断裂 | 每页单看都对，连起来链条断了；上一页的疑问下一页不接 |
| 量化缺失 | "显著提升""几乎无效"——没有数字、基准、条件 |
| 观点隐含 | 整页罗列事实，核心观点留给听众自己推断 |
| 术语误用 | 准确率/精确率混用、鲁棒性不带威胁模型、引用与方法名称对不上 |
| 跨页自相矛盾 | 同一构念多种叫法；正文声明的任务形式与实现不一致 |

通用大模型能给出"建议表达更清晰"这类无法执行的意见。本技能要做的是**定位到页、引用原文、给出可直接粘贴的改写**。

## 四项审查标准

逐页强制质询，每条问题必须映射到其中一项：

### 标准一 · 背景与场景
- 关键术语是否在此前或本页定义过？首次出现即使用 → 背景缺失
- 问题背景是否交代完整：任务设定、数据、假设、约束（AI 安全类须回答威胁模型三要素）
- 是否有模糊表述：「传统方法」「现有方法存在不足」「效果很好」——无引用、无数字、无对象即为场景含糊
- 上下文是否断裂：本页结论依赖的前提是否在前文出现过

### 标准二 · 逐页因果
- **存在性**：删掉这一页，论证链是否断裂？不断裂 → 页面冗余
- **承上**：上一页留下的疑问，本页是否回应？
- **启下**：本页应留下的疑问，下一页是否接住？
- **顺序依据**：本页为何在这个位置？说不出依据 → 顺序失据

### 标准三 · 逻辑结构
- 页内链条：主张 → 证据 → 推理 → 小结，是否完整？
- 因果语言是否规范（「证明/表明/导致/相关」须与证据强度匹配）
- 是否有明确小结（takeaway）？
- 量化：性能断言是否附数字、基准、条件？
- 目的与结论是否可见？

### 标准四 · 观点表达
- 本页陈述断言，还是罗列事实？
- 标题是断言式（"X 在低资源场景下优于 Y，因为 Z"）还是主题式（"实验结果"）？
- 核心贡献是否被显式说出？
- 观点与证据是否匹配？有无过度声明？

## 工作流

```
① 内容提取 ──→ ② 全局定位 ⟶ ●检查点A ──→ ③ 逐页四项标准审查
                                              ↓
⑥ 汇总输出 ⟵ ●检查点B ⟵ ⑤ 领域严谨性核查 ⟵ ④ 相邻页衔接 + 跨页一致性核查
```

1. **内容提取**：解析 `.pptx` 逐页结构化内容（标题/层级正文/表格/备注），并导出嵌入图片——**图形页必须看图再下结论**，核心论据往往只在图里。
2. **全局定位**：先用一句话复述核心主张（复述不出即是全局性问题）、判断受众与场合、还原叙事主线、检查首尾呼应。
3. **逐页审查**：先做**标题断言式扫描**（全片一次性，逐条判定标题是断言式还是主题式），再四项标准逐页强制质询，末尾产出**四标准覆盖表**（任一列为空须说明理由，留空视为未审）。
4. **衔接与一致性**：相邻页承接专项 + **跨页一致性核查**（术语一致性 / 构念与实现一致性 / 数字与名称一致性）——组会汇报中最致命的问题是"各页单看都对，合起来自相矛盾"。
5. **领域严谨性核查**：对照领域清单核查术语精度、因果语言、AI 安全专项（威胁模型、自适应攻击）、CV 专项（指标协议、可视化证据地位）。
6. **汇总输出**：按固定五段格式出报告，附**修改优先级路线图**（先改什么后改什么）。

**两个检查点**（防止自主失控）：

- **检查点 A · 全局定位确认**：定位摘要（核心主张／受众／主线／首尾呼应／审查重点预判）先给用户确认，再进入逐页审查——定位错了，整份清单会集体跑偏。无法交互时自行继续，摘要仍写入报告开头。
- **检查点 B · 输出规模确认**：问题 >20 条或 🔴≥3 条时，先给一行总览（条数分布 + Top3）再出完整报告；未达阈值不打断。

## 输出规范

严重级三级：

| 级别 | 判定 |
|---|---|
| 🔴 必须修改 | 概念错误 / 论证前提被推翻 / 核心主张缺失 / 度量协议不清 |
| 🟡 建议修改 | 表述模糊 / 量化缺失 / 观点隐含 / 转场不显式 |
| 🟢 可选优化 | 顺序可调 / 页面可合并 |

**承接类问题**按"翻过这页，读者能否自行补上那层因果"判定：上一页的前提被下一页推翻 → 🔴；仅缺显式转场句但可自行推断 → 🟡。

每条问题固定三字段：

```markdown
- [P7 | 🔴 | 实验设置缺失]
  **定位**：「（逐字引用原文）」
  **问题**：违反哪项标准 + 为何不合格
  **建议**：（可直接粘贴的改写措辞 / 需补充的具体数据点 / 明确的页面操作）
```

**输出纪律（硬约束）**：逐字引用原文定位；建议必须可执行，禁止"建议进一步优化"类空话；问题超过约 30 条时生成可勾选的 HTML 报告。

## 安装

将本仓库放入客户端的 skills 目录：

```bash
git clone https://github.com/Julien000/ppt-review.git

# WorkBuddy（用户级，跨项目可用）
cp -r ppt-review ~/.workbuddy/skills/

# Claude Code 等兼容 Agent Skills 的客户端（项目级）
cp -r ppt-review <项目目录>/.claude/skills/
```

依赖：

```bash
pip install python-pptx
```

## 使用

在会话中把 PPT 交给 Agent 并点名技能即可：

```
@"20260910-xxx-进度汇报.pptx" ppt-review
```

或自然语言触发（技能描述中已覆盖这些说法）：

- "帮我审查一下这个 PPT / 幻灯片 / 答辩稿"
- "这个组会汇报有什么逻辑问题"
- "批改一下我的开题报告演示"

也支持**页面截图**（逐页 Read 后可评估图形内容）与**粘贴文本**。

### 手动运行提取脚本

```bash
python scripts/extract_pptx.py deck.pptx -o deck.md --imgs ./imgs
```

输出示例（节选）：

```
## Slide 5/14
标题: 实验方案
- 基于特征反演和参数扰动构建触发器
  - 隐蔽性差，不太专业
[视觉元素] 图片×6 表格×0 图表×0 · 正文字数≈103
[已导出图片] P05_05_120k.png（用 Read 工具核验后纳入审查结论）
[备注] 这里的核心思想就是在优化触发器的过程中就模拟模型修改
```

## 适用边界

**擅长**：学术论证链的完整性与概念精度审查——这是通用审阅最薄弱、而导师最苛刻的部分。

**不做**：
- 排版美学（除非文字密度已淹没论证主线）
- 替代作者撰写 PPT（创建 PPT 请用 `pptx` 技能）
- 图形内容的真实性核验（如论文原表的数据是否正确，只审查其呈现方式）

**已知局限**：SmartArt、艺术字、嵌入图片内的文字无法通过 python-pptx 提取，此类页面会被标注"需人工核对视觉信息"，相关结论会在报告末尾的《审查局限声明》中说明。
